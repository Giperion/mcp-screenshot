# План: screenshot MCP на C# (переписывание с нуля)

Рабочая ветка: `claude/upbeat-ride-rbs8j5` (создана от `main`).

## 1. Исходные условия

- **Пишем с нуля.** Python-версия удалена из ветки, её код и алгоритмы не переносятся. Из неё взят только список возможностей, которые нужны пользователю.
- **Известный баг старой версии:** один из инструментов скрывает окно приложения. Причина не установлена. В старой версии окна меняли только `focus_window` и `screenshot_window` с `bring_to_front`: `ShowWindow`, подключение к чужим потокам ввода и эмуляция нажатия Alt. Остальные инструменты только читали. Новая версия исключает такие эффекты за счёт устройства (раздел 3) и проверяет это тестом (раздел 12).

### Принятые решения

| Вопрос | Решение |
|---|---|
| Зависимости | Можно требовать установленный **.NET 10 Runtime**. NativeAOT пока не делаем. |
| Все мониторы разом | **Одна склеенная картинка** (приложение может быть растянуто на два монитора). |
| Минимальная Windows | **Windows 10 1809+** (минимум для WinRT-проекции Windows SDK; более старые сборки Win10 давно без поддержки). WGC используется, где доступен (1903+), иначе fallback. |
| Формат картинки | **PNG** в ответе инструмента (раздел 8). JPEG/WebP не нужны. |

## 2. Цели

- **Снимок отдельного окна.** Работает, даже если окно перекрыто другими, и для GPU/DirectX-окон (игры, UnrealEditor, браузеры). Фокус окну для этого не нужен. Окно, растянутое на два монитора, снимается целиком.
- **Снимок экрана с выбором монитора.** По номеру или имени, нумерация стабильна между запусками.
- **Снимок всех мониторов разом:** одна склеенная картинка всего виртуального экрана.
- **Картинку может открыть любая модель:** стандартный MCP-блок `image` в PNG, размер в пределах лимитов моделей.
- **Поиск окон и мониторов; перевод фокуса** только по явному запросу.
- **Сборка:** exe + .NET 10 Runtime, сборка и тесты в CI, бинарники в GitHub Releases.

## 3. Принципы

1. **Съёмка и поиск не меняют окна.** Инструменты `screenshot_*`, `find_window` и `list_monitors` только читают. Код, который меняет состояние окон, вынесен в отдельный компонент `WindowStateController`. Сервисы захвата и поиска на него не ссылаются.
2. **Окна меняются только по явному запросу:** `focus_window`, `bring_to_front`, `restore_minimized`. Изменение минимальное, через документированные API. Без эмуляции клавиатуры и мыши, без подключения к чужим потокам ввода.
3. **Временное изменение откатывается.** Например, свёрнутое окно развернули ради снимка — в `finally` сворачиваем обратно, в том числе при ошибке.
4. **Побочные эффекты видны в ответе.** До и после любого изменения делается снимок состояния окон, в ответе перечисляется, что поменялось. Пример: полноэкранная игра сама свернулась при потере фокуса.
5. **Требования к точности:**
   - границы окна без невидимых рамок Win10/11 (`DWMWA_EXTENDED_FRAME_BOUNDS`);
   - стабильная нумерация мониторов;
   - качественное уменьшение, мелкий текст остаётся читаемым;
   - layered-окна (тултипы, оверлеи) попадают на снимок экрана;
   - проверка регионов;
   - честное согласование версии протокола.

## 4. Технологии

| Что | Выбор | Почему / альтернатива |
|---|---|---|
| Runtime | **.NET 10 (LTS)**, TFM `net10.0-windows10.0.19041.0` | Поддержка до конца 2028 г. TFM с версией Windows SDK нужен для WinRT-проекции Windows.Graphics.Capture. Хватает обычного .NET Runtime, Desktop Runtime не нужен. |
| MCP | Официальный SDK **`ModelContextProtocol`** (NuGet), stdio-транспорт | Согласование версии протокола, отмена, ping, атрибуты инструментов, аннотации. |
| Win32 | **`Microsoft.Windows.CsWin32`** (source generator, `NativeMethods.txt`) | Готовые безопасные сигнатуры и SafeHandle. Альтернатива: ручные `[LibraryImport]`. |
| Захват окон | **Windows.Graphics.Capture** (WGC) + **PrintWindow** (`PW_RENDERFULLCONTENT`) + GDI `BitBlt` как крайний вариант | См. раздел 6. |
| Захват экрана | GDI `BitBlt` + `CAPTUREBLT`; WGC `CreateForMonitor` для полноэкранных игр | См. раздел 7. |

| Масштабирование | Своё box/bilinear-уменьшение по BGRA-буферу | Читаемый текст после даунскейла. |
| DPI | `app.manifest`: `PerMonitorV2` | Физические пиксели на всех мониторах с любым масштабом. |
| Тесты | xUnit v3 на Microsoft Testing Platform | Протокольные тесты гоняют настоящую регистрацию сервера через in-memory потоки и клиент из MCP SDK. |
| Публикация | Framework-dependent single-file `win-x64` + `win-arm64` | Один exe (~29 МБ, из них ~25 МБ — проекция Windows SDK), нужен установленный .NET 10 Runtime. Уменьшить можно позже через self-contained + trimming или NativeAOT. |

## 6. Захват отдельного окна

Параметр `method`: `auto` (по умолчанию) | `wgc` | `printwindow` | `screen`.

| Бэкенд | Перекрытое окно | GPU/DirectX | Нужен фокус | Минусы |
|---|---|---|---|---|
| `wgc` (Windows.Graphics.Capture) | ✓ | ✓ | нет | Win10 1903+, D3D11-устройство; первый кадр через ~50–100 мс; на Win10 жёлтая рамка на время съёмки (на Win11 отключается `IsBorderRequired = false`) |
| `printwindow` (`PW_RENDERFULLCONTENT`) | ✓ | часто ✓ | нет | Некоторые окна отдают чёрный кадр |
| `screen` (кусок экрана по границам окна) | ✗ | ✓ | да, если перекрыто | Снимает то, что видно на экране |

Стратегия `auto`:
1. **WGC**, если доступен.
2. Иначе **PrintWindow**. Если кадр целиком чёрный или пустой, переходим к п. 3.
3. Иначе **screen**. Если окно перекрыто, окно не трогаем: в ответе предупреждение и подсказка про `bring_to_front`.

Бэкенд, которым сделан снимок, указывается в ответе.

- **Свёрнутое окно:** ни один бэкенд его не снимает. По умолчанию возвращается понятная ошибка. С `restore_minimized: true` окно разворачивается без активации, снимается и сворачивается обратно без активации (через `WindowStateController`, с откатом в `finally`).
- **`client_only`:** клиентская область вырезается из полного кадра, работает для всех бэкендов.
- **`bring_to_front`:** нужен только для `screen`. Вызывает тот же код, что `focus_window`.

## 7. Экран и мониторы

- **Модель монитора:**
  - `index`;
  - `device_name` (`\\.\DISPLAY1`);
  - `friendly_name`, например «DELL U2720Q» (через `QueryDisplayConfig` + `DisplayConfigGetDeviceInfo`);
  - `primary`, `rect`, `work_area`, `dpi`, `scale`.
- **Стабильная нумерация:** сортировка по номеру `DISPLAYn`. Он не меняется между запусками и обычно совпадает с нумерацией в настройках Windows (проверяется на реальной машине). `monitor` принимает число или строку (`"DISPLAY2"`, подстроку `friendly_name`). Без `monitor` снимается основной монитор.
- **Все мониторы (`all_monitors: true`):** одна склеенная картинка всего виртуального экрана.
  - Промежутки между мониторами разного размера или со смещением заливаются чёрным.
  - В тексте ответа перечислены мониторы и их прямоугольники на картинке.
  - При уменьшении под лимиты (раздел 8) детали на широкой склейке мельчают. Если модели нужен текст, она может запросить один монитор или регион; это сказано в описании инструмента.
- **Регион** `x/y/width/height` в координатах виртуального экрана обрезается по его границам. Если регион с экраном не пересекается, возвращается ошибка.
- **Бэкенд:** GDI по умолчанию, `method: "wgc"` для полноэкранных игр, где GDI даёт чёрный кадр.

## 8. Формат изображения для моделей

**Как отдаём.** Стандартный MCP-блок `{"type": "image", "data": <base64>, "mimeType": "image/png"}` в результате инструмента. MCP-клиенты (Claude Code, Claude Desktop, Cursor и др.) передают такой блок модели как изображение. На диск ничего не пишется.

**Почему PNG.** Его понимают все модели с поддержкой изображений. Claude принимает `image/png`, `image/jpeg`, `image/gif`, `image/webp`. PNG без потерь, текст и тонкие линии UI остаются чёткими. JPEG-артефакты, по документации Anthropic, мешают модели читать текст.

**Лимиты Claude** (документация Vision, 2026):

| Ограничение | Значение |
|---|---|
| Максимальное разрешение, которое модель реально использует | Claude 4.7 и новее: длинная сторона 2576 px и не более 4784 визуальных токенов (патч 28×28, ≈3,75 Мп). Старые модели: 1568 px / 1568 токенов. Картинку крупнее модель сама уменьшает. |
| Абсолютный максимум | 8000×8000 px. Если в запросе больше 20 картинок, то не более 2000 px по каждой стороне. |
| Размер одной картинки (в base64) | 10 МБ в Claude API; 5 МБ в Amazon Bedrock и Google Cloud |
| Стоимость | `⌈w/28⌉ × ⌈h/28⌉` токенов. 1920×1080 ≈ 2691 токен. |

**Политика размера по умолчанию** (класс `ImageFitter`):
1. **`max_size`** — ограничение длинной стороны, по умолчанию **2576 px**. Дополнительно площадь не больше ≈3,75 Мп. Больше модель всё равно не увидит, лишние пиксели только увеличивают ответ. Монитор 1920×1080 отдаётся без уменьшения, 4K — как 2576×1449. `max_size: 0` означает нативное разрешение (в пределах байтового бюджета).
2. **Байтовый бюджет:** base64 не больше **~4,5 МБ**, чтобы проходить и самый строгий лимит в 5 МБ. Если PNG не влезает (типично для игр и фото), картинка уменьшается ступенями (~×0,85) и кодируется заново, пока не влезет.
3. **Метаданные в ответе:** исходный размер, итоговый размер, коэффициент масштаба и смещение источника в экранных координатах. По ним модель переводит точку на картинке в координаты экрана.

Бюджет и `max_size` по умолчанию можно поменять аргументом командной строки или переменной окружения в `mcp.json`. Собственные лимиты разных MCP-клиентов на размер ответа проверяются вручную (раздел 12).

## 9. Фокус окна (`focus_window`)

1. Снимок состояния всех окон (`WindowStateSnapshot`).
2. Если окно свёрнуто и `restore: true`, оно разворачивается (`ShowWindow(SW_RESTORE)`), только целевое окно.
3. `SetForegroundWindow`.
4. Если Windows отказала (защита от кражи фокуса), пробуем документированный путь через UI Automation `SetFocus`. Если и он не сработал, возвращаем ошибку `focus_blocked` и мигаем окном в таскбаре (`FlashWindowEx`). Нажатий клавиш и других хаков нет.
5. Повторный снимок и сравнение. В ответе:
   - удалось ли перевести фокус;
   - текущее состояние целевого окна;
   - список других окон, у которых изменилось состояние (свернулись, скрылись).

Будет ли работать вариант с UI Automation, проверяется на этапе spike.

## 10. API инструментов

Инструменты проектируются заново. Имена удобные, поэтому остаются прежними.

| Инструмент | Параметры | Меняет окна |
|---|---|---|
| `screenshot_screen` | `monitor` (int или строка), `all_monitors`, `x/y/width/height`, `max_size`, `include_cursor`, `method` | нет |
| `screenshot_window` | `hwnd` / `title` / `process`, `client_only`, `method`, `max_size`, `include_cursor`, `restore_minimized`, `bring_to_front` | только с `restore_minimized` / `bring_to_front` |
| `find_window` | `hwnd` / `title` / `process`, `limit`, `include_minimized` | нет |
| `list_monitors` | — | нет |
| `focus_window` | `hwnd` / `title` / `process`, `restore` | да |

- **Аннотации MCP:** `readOnlyHint` у всех, кроме `focus_window`. У `screenshot_window` изменения по опциям описаны в описании параметров.
- **Ответ со снимком:** сначала image-блок PNG, потом текст с метаданными (источник, координаты, размеры, масштаб, бэкенд, предупреждения). Модели лучше работают, когда картинка идёт перед текстом.
- **Идентификация окна:** `hwnd` в формате `0x…`. Неоднозначный `title`/`process` даёт ошибку со списком кандидатов.

Каждый этап отдельным коммитом в ветку; после каждого проект собирается и тесты проходят.

7. **Захват окон.** WGC → PrintWindow → screen, стратегия `auto`, `client_only`.
8. **Изменение состояния окон.** `WindowStateController`, `focus_window`, `restore_minimized`, `bring_to_front`, отчёт о побочных эффектах.
9. **CLI для ручной проверки:** `--list`, `--screenshot out.png [--monitor N | --all | --window 0x…]`.
10. **Тесты** (раздел 12).
11. **Документация:** README / README_RU, `mcp.json.example` под `.exe`, требование .NET 10 Runtime.
12. **Релизы.** Workflow по тегу `v*`: публикация `win-x64` и `win-arm64`, zip в GitHub Release.

## 12. Тестирование

- **Главный регрессионный тест (против бага «окно пропадает»).** `TestWindowHost` создаёт окна в разных состояниях: обычное, развёрнутое, свёрнутое, перекрытое, topmost, полноэкранное без рамки, растянутое на два монитора. Для каждого инструмента, кроме `focus_window`, и для каждого бэкенда: снимок состояния всех окон до вызова совпадает со снимком после. Сравниваются видимость, свёрнутость, развёрнутость, границы, окно с фокусом и z-порядок. Для `focus_window`: целевое окно видимо и в фокусе, у остальных окон меняются только z-порядок и фокус.
- **Юнит-тесты:**
  - PNG-энкодер (декодировать обратно и сравнить пиксели, для всех фильтров);
  - `ImageFitter`: лимит длинной стороны, площади и байтового бюджета;
  - масштабирование и метаданные координат;
  - парсинг `hwnd` и `monitor`;
  - склейка мониторов с отрицательными координатами и промежутками;
  - обрезка регионов;
  - выбор бэкенда в `auto` (через фейки);
  - неоднозначный поиск окна.
- **Протокол:** запуск exe как процесса, `initialize` → `tools/list` → снимок `inputSchema`; `tools/call` с неверными аргументами возвращает `isError`; ответ со снимком содержит валидный PNG в пределах бюджета.
- **Захват:** перекрытое тестовое окно с известной заливкой снимается через `wgc`/`printwindow` с правильными цветами; снимок монитора не пустой.
- **Ручная проверка на реальной машине:**
  - 2+ монитора с разным DPI;
  - окно, растянутое на два монитора;
  - игра или UnrealEditor в полноэкранном режиме;
  - браузер;
  - свёрнутое окно;
  - Claude Code, Claude Desktop и Cursor как MCP-клиенты: модель видит картинку, лимиты клиентов не срабатывают.

Ограничение: облачный контейнер, где я работаю, — Linux. Там собирается решение (`EnableWindowsTargeting`) и проходят тесты без Win32, но захват реально проверяется только на Windows, то есть в CI на `windows-latest` и на вашей машине. Тесты, которым нужен рабочий стол, помечаются `[Trait("Category","Desktop")]` на случай, если в CI рабочего стола не окажется.

## 13. Риски

| Риск | Что делаем |
|---|---|
| WGC недоступен (Windows 10 до 1903, сессия без GPU, RDP) | `auto` откатывается на PrintWindow → screen, бэкенд указывается в ответе. |
| Жёлтая рамка WGC на Win10 | Только на время съёмки (сессия закрывается сразу после кадра); на Win11 отключается. |
| PrintWindow отдаёт чёрный кадр у части приложений | Детект пустого кадра и переход к следующему бэкенду. |
| Windows не даёт перевести фокус | Честная ошибка `focus_blocked` + мигание в таскбаре, без хаков. |
| Полноэкранные приложения сворачиваются сами при потере фокуса | Этого не избежать при смене фокуса. Съёмка окон фокус не трогает, а `focus_window` сообщает о таком эффекте в ответе. |
| PNG игровой сцены слишком большой | Байтовый бюджет и ступенчатое уменьшение (раздел 8). |
| Склейка 3+ мониторов после уменьшения нечитаема | В ответе список мониторов; модель может запросить монитор или регион отдельно. |
| У MCP-клиента свой лимит на размер ответа | Бюджет настраивается; проверяем Claude Code, Claude Desktop, Cursor на этапе spike. |
